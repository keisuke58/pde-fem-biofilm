## 1. 第5章の方針

**Ch5 = ANSYS 材料則の寄与**（このリポジトリの `ansys_usermat/`、Oliver
フレームワークへの統合）。既に書いてある JAXFEM ベースの Ch5 草稿は
**慶應用に温存**し、今回は提出しない。

これは方針転換ではなく、[`THESIS_PLAYBOOK.md`](THESIS_PLAYBOOK.md) §4 が
もともと引いていた線を具体化したものです：

```
T1  修論（LUH、今）      ANSYS USERMAT + 成長則 + 引き渡し      → Ch5
T3  継続（慶應）          JAXFEM、カップリング、phase-field 等   → 温存
```

この順序が正しい理由は2つ。章の中でも述べる価値があります：

- **課題設定にそのまま答えている。**
  [`THESIS_ASSIGNMENT.md`](THESIS_ASSIGNMENT.md) §1 の課題は
  *「点ごとの TMCMC モデルを、既存の動く FEM フレームワークに統合し、
  空間的効果を表現できるようにする」*。Oliver のフレームワークが
  **その「既存の動くフレームワーク」そのもの**です。JAXFEM は自前の
  フレームワークで、良いものではあるが、別の問いに答えている。
- **検証済みなのがこちらだから。** コアは Abaqus UMAT に対して 8017 状態で
  0 ULP 一致、ラッパーもそれを継承（PR #46）。新しい物理を足さずに章が
  書ける — FREEZE 原則が求めているのはまさにこれです。

## 2. Ch5 が「今日すでに」主張できること

計画全体の要になる部分です。**Tier A の内容は既にすべて事実**であり、
そこには他人のカレンダー待ちが一つも入っていない — その状態で章を書きます。

### Tier A — 完了・検証済み・リポジトリにある

| 主張 | 根拠 |
|---|---|
| 成長＋粘弾性の構成則を ANSYS USERMAT として実装 | `ansys_usermat/usermat_biofilm.f` |
| 独立実装の Abaqus UMAT と数値的に一致 | `crosscheck/` + `adversarial.py`、8017状態で 0 ULP |
| 相手のフレームワークの呼び出し口にそのまま挿せる形に整形 | `biofilm_material_v01.f`、`BIOFILM_GROWTH_VISCO_V01` |
| 整形によって物理は一切変わっていない | `test_wrapper_is_only_an_adapter`、rtol=0 atol=0 |
| 成果物は ANSYS バージョン非依存 | ANSYS include / common block / UPF 呼び出しなし（相手の `AceGenNeoHookV04` と同じ） |
| インターフェース上の制約を仮定でなく実測で特定 | `Fv` は9成分必要（非対称性 ~6e-5 を実測）、`dt` は `η/(2·C10)` を解像する必要（`dt/τ≈0.5` で σ₁₁ が符号反転） |

これで「手法＋検証」の章としては完結しています。単独で口頭試問に耐えます。

## 3. クリティカルパス — 短くする一手

統合プランの4ステップは、順序より依存関係のほうが重要です：

| ステップ | 状態 | 依存先 |
|---|---|---|
| 2. コアを相手の呼び出し規約に合わせる | ✅ 完了（PR #46） | 自分 |
| 3. ラッパーを検証 | ✅ 完了（PR #46） | 自分 |
| 1. ANSYS v222 へローカル移植 | **次** | 自分＋このPC |
| 4. 相手がフレームワークに組み込む | 未 | **Oliver のカレンダー** |

**ステップ1の優先度は上がりました。** 元は「現実的なテストベッドであって
前提条件ではない」という位置づけでしたが、11月締切だとそれ以上の意味を
持ちます。ローカルの v222 ビルドが通れば、**ステップ4を待たずに**自前で
ANSYS ジョブを回して Tier B の結果を出せる。つまり、こちらが制御できない
唯一の依存を「あれば嬉しいもの」に格下げできます。

したがって：**Tier B はステップ1だけで到達可能でなければならない。**
ステップ4が提出前に着地すれば素晴らしいし章にも書きますが、
章をそれ前提で書いてはいけません。

## 4. Soleimani 先生・Oliver とのやり取り

短く・定期的に・オンラインで。狙いは二人が驚かないことです。

| 頻度 | 相手 | 形式 |
|---|---|---|
| **隔週** | Meisam | 短い書面報告 — 完了・次・詰まっている点。5行で十分 |
| **月次** | Meisam | オンライン通話 — スコープ、章構成、出てきた結果 |
| **節目ごと** | Oliver | 書面、1回1トピック — 引き渡し一式 → インターフェース注意点 → 組み込み |
| **引き渡し時に1回** | Oliver | ルーチンを渡すときにオンラインで話す（注意点を読まれるだけでなく議論されるように）。時期は下の注記に従う |

先送りせず早めに出す2件：

1. **提出日の確定**を Meisam に（第1週）。
2. **Ch5 のスコープを Meisam に明示的に合意**（第1〜2週）。JAXFEM を
   温存する件も含めて。11月に驚かせるより、今 承認をもらう形にする。

**Oliver への引き渡しは、意図的にこの一覧から外しました（2026-09-02 改訂）。**
以前は第2〜3週に置いていて、根拠は「ステップ4を成立させるには相手に
リードタイムが要る」でした。その根拠はステップ1が着地した時点で消えています
— 上の §3 が「Tier B はステップ1だけで到達可能でなければならず、章は
ステップ4を前提に書いてはならない」と結論している以上、提出に必要なもので
相手のカレンダーに依存するものは何もありません。早く送っても修論には
何の得もなく、相手の予定をこちらのクリティカルパスに乗せるだけです。
一式そのものは既にできているので、送りたいときに送れます。

送るのは **Ch5 の結果が出た後**。完成した章と一緒に、本来の意味での
「貢献の返礼」として渡すのが自然です。これを覆す条件は一つだけで、上の
スコープ決定です — Ch5 が「相手のフレームワークに*組み込んで動いた*」と
主張するなら（「組み込める形にした」ではなく）、それは確かに Oliver の
リードタイムを要するので、Meisam がそのスコープに同意した瞬間に引き渡しは
急ぎに変わります。**主張を先に決め、送るのは後**。逆順にしないこと。
